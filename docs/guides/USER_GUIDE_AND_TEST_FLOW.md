### 部署方式一：Java 后端启动（推荐）

Java 后端提供更好的性能和企业级特性，适用于生产环境。

#### 方式 1.1: Docker 一键部署（推荐）

```bash
# 1. 进入项目目录
cd "Jieli Education Smart Cloud Platform"

# 2. 启动 Java 后端服务（首次需要下载镜像，约5-10分钟）
docker-compose -f docker-compose.java.yml up -d

# 3. 等待数据库初始化完成（约30秒）
sleep 30

# 4. 验证服务状态
curl http://localhost/api/v1/health
docker-compose -f docker-compose.java.yml ps
```

#### 方式 1.2: 本地开发启动

```bash
# 1. 进入 Java 后端目录
cd backend-java

# 2. 使用 Maven 启动（开发模式）
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

# 或构建后启动
./mvnw clean package -DskipTests
java -jar target/jieli-education-*.jar --spring.profiles.active=dev

# 3. 后端服务将在 http://localhost:8080 启动
```

#### 方式 1.3: IDE 开发启动

```bash
# 1. 使用 IntelliJ IDEA 或 Eclipse 打开 backend-java 目录
# 2. 等待 Maven 依赖下载完成
# 3. 运行 JieliEducationApplication 主类
# 4. 或使用 IDE 的 Spring Boot 运行配置
```

## 一、系统概述

### 1.1 平台定位

**接力教育智慧云平台**是为"广西北部湾人工智能大赛（湾赛）"打造的在线考试与练习平台，支持：
- 赛前练习与题库训练
- 赛中在线考试与实时监控
- 赛后成绩管理与审分配合

## 三、比赛前业务流程

### 3.1 激活计划管理流程（管理员）

**业务场景**: 管理员需要配置不同类型的激活计划，作为生成激活码的权限模板

```
┌─────────────────────────────────────────────────────────────────┐
│                    激活计划配置流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │

│  ┌──────────────────────────────────────────────────────────┐   │
│  │ • 计划名称（如：小学教师年卡）                              │   │
│  │ • 目标角色（teacher/student）                              │   │
│  │ • 适用学段（primary/middle/high）                          │   │
│  │ • 有效期（365天 / -1永久）                                  │   │
│  │ • 价格（线上销售用）                                        │   │

│                              ↓                                   │

│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**测试要点**:
1. 创建四类标准计划：小学教师、小学学生、初中教师、初中学生
2. 验证权限配置的保存和读取
3. 验证计划停用后不能生成新激活码
4. 验证已有激活码不受计划后续修改影响（权限快照机制）

## 八、故障排查指南

### 8.1 常见登录问题

| 问题现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 账号不存在 | 账号未注册/输入错误 | 检查身份证号/用户名，确认账号已激活 |
| 密码错误 | 密码输入错误 | 使用初始密码或重置密码 |
| 账号被禁用 | 账号被管理员禁用 | 联系管理员启用账号 |
| 被强制退出 | 账号在其他设备登录 | 确认是否本人操作，修改密码 |
| 考试未开始 | 未到场次开放时间 | 查看考试开始时间，等待开放 |

### 8.2 常见答题问题

| 问题现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 无法提交 | 主观题未上传 | 上传主观题后再提交 |
| 上传失败 | 文件过大/格式错误 | 检查文件大小(<10MB)和格式 |
| 进度未保存 | 网络断开 | 检查网络，重新登录恢复 |
| 页面卡顿 | 浏览器兼容性问题 | 更换Chrome/Firefox浏览器 |
| 时间显示异常 | 本地时间不准确 | 同步系统时间 |

### 8.3 练习账号常见问题（新增）

| 问题现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 练习账号无法登录 | 账号未生成/密码错误 | 检查账号格式PRA_PRI_xxxxxx，确认密码 |
| 练习账号显示考试菜单 | 账号类型识别错误 | 检查账号类型是否为"practice" |
| 练习记录未保存 | 练习模式数据隔离 | 检查练习记录是否在独立表中 |
| 练习账号看不到题库 | 题库权限未配置 | 检查激活计划是否配置了题库权限 |
| 练习成绩影响正式成绩 | 数据隔离问题 | 确认练习与考试数据表完全分离 |
| 批量生成失败 | 数量超出限制 | 检查生成数量是否在300-600范围内 |
| 账号格式错误 | 学段参数错误 | 确认学段为primary/junior |

### 8.4 系统运维问题

| 问题现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 服务无法启动 | 数据库连接失败 | 检查MySQL/Redis服务状态 |
| 高并发卡顿 | 服务器资源不足 | 扩容服务器或开启CDN |
| 数据不一致 | 并发操作冲突 | 检查事务隔离级别，修复数据 |
| 激活码泄露 | 批次管理不善 | 作废泄露批次，重新生成 |

### 8.5 Java 后端常见问题（新增）

| 问题现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 端口冲突 8080 | 端口已被占用 | 修改 `application.yml` 中的 `server.port` 或停止占用端口的进程 |
| 内存不足 OOM | JVM 堆内存设置过小 | 调整启动参数：`-Xms512m -Xmx2g` |
| 数据库连接超时 | 连接池配置不当 | 检查 `spring.datasource.hikari` 配置，调整最大连接数 |
| 编译失败 | Maven 依赖未下载 | 执行 `./mvnw clean install -U` 强制更新依赖 |
| 热部署不生效 | Spring Boot DevTools 未配置 | 确保 `spring-boot-devtools` 在依赖中，IDE 启用自动编译 |
| API 文档无法访问 | Swagger 配置问题 | 访问 `/swagger-ui.html` 或 `/api/v1/docs` |
| 跨域问题 | CORS 配置缺失 | 检查 `CorsConfig` 配置，确保前端域名在允许列表中 |
| 启动缓慢 | 懒加载未启用 | 在 `application.yml` 中设置 `spring.main.lazy-initialization: true` |

#### Java 后端内存配置建议

```bash
# 开发环境（2GB 内存）
java -Xms256m -Xmx1g -jar jieli-education.jar

# 生产环境（4GB+ 内存）
java -Xms1g -Xmx2g -XX:+UseG1GC -jar jieli-education.jar

# Docker 环境（通过环境变量配置）
environment:
  - JAVA_OPTS=-Xms512m -Xmx1g -XX:+UseContainerSupport
```

#### 端口冲突解决方案

```bash
# 1. 查找占用 8080 端口的进程
lsof -i :8080
# Windows: netstat -ano | findstr :8080

# 2. 终止占用进程
kill -9 <PID>
# Windows: taskkill /PID <PID> /F

# 3. 或在 application.yml 中修改端口
server:
  port: 8081  # 修改为其他端口
```

### B.8 数据重置与前端构建命令

#### 重新导入演示数据

```bash
# 方式1：使用 docker-compose 执行
```

**注意**：重新导入会清空现有演示数据，请确保已备份重要数据。

#### 前端重新构建（解决显示问题）
如果修改了前端代码（如教师工作台统计修复），需要重新构建前端：

```bash
# 进入前端目录
cd frontend

# 安装依赖（如未安装）
npm install

# 构建生产版本
npm run build

# 或使用 Docker 构建
docker-compose -f docker-compose.simple.yml up -d --build frontend
```

#### 后端重启命令
修改后端代码后需要重启：

```bash
# 重启后端服务
docker-compose -f docker-compose.simple.yml restart backend

# 或重新构建后端
docker-compose -f docker-compose.simple.yml up -d --build backend
```

#### 一键重置所有（数据+前端+后端）
```bash
# 停止所有服务
docker-compose -f docker-compose.simple.yml down

# 重新构建并启动
docker-compose -f docker-compose.simple.yml up -d --build

sleep 10 && docker-compose -f docker-compose.simple.yml exec backend python /app/scripts/import-demo-data.py
```
