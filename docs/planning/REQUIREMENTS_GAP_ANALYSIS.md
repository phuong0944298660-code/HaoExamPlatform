## 三、代码审查发现的关键问题（v2.0 新增）

> 以下问题通过逐文件代码审查发现，是初版需求对比中未覆盖的实际实现缺陷。

### 3.0 🔴 致命：前端页面使用Mock假数据（后端API已就绪但未对接）

这是当前系统最严重的问题。3个教师端核心页面和1个学生端页面**完全使用硬编码假数据**运行，对应的后端API和前端API封装均已完成但从未被调用。

#### 3.0.1 教师端 `Scores.vue` — 成绩管理（100% Mock）

**现状**:
- `mockExamList` 硬编码考试列表
- `generateMockScores()` 用 `Math.random()` 生成456条随机成绩
- `fetchExamList()` 用 `setTimeout` 模拟API延迟
- `handleExport()` 用 `setTimeout` 模拟导出成功
- `handleViewDetail()` 仅显示 `message.info()` 提示

**已就绪但未调用的API**:
- `frontend/src/api/scores.ts` → `getScores()`, `exportScores()`
- `app/api/v1/scores.py` → `GET /`, `GET /export`

**影响**: 教师无法查看真实学生成绩、无法导出成绩表

#### 3.0.2 教师端 `Resources.vue` — 资源中心（100% Mock）

**现状**:
- `mockResources` 硬编码6条假资源记录
- `fetchResources()` 用 `setTimeout` 模拟
- `customUpload()` 用 `setInterval` 模拟上传进度
- `handleDelete()` 仅从本地数组删除，不调用API

**已就绪但未调用的API**:
- `frontend/src/api/resources.ts` → `getResources()`, `uploadResource()`, `deleteResource()`
- `app/api/v1/resources.py` → `GET /`, `POST /`, `DELETE /{id}`

**影响**: 资源中心完全不可用，上传的文件不会保存到服务器

#### 3.0.3 教师端 `ExamDashboard.vue` — 考试实时监控（100% Mock）

**现状**:
- `loadExamData()` 返回硬编码考试信息
- `loadStudents()` 用 `weightedRandom()` 生成456条假学生状态数据
- `handleForceSubmit()` 仅修改本地 `record.status`，不调用API
- `handleMarkAbnormal()` 仅修改本地状态

**已就绪但未调用的API**:
- `frontend/src/api/exams.ts` → `getExamDashboard()`, `getExamStudents()`
- `app/api/v1/exams.py` → `GET /{id}/dashboard`, `GET /{id}/students`

**影响**: 教师无法实时监控考试状态，强制提交/标记异常功能不可用

#### 3.0.4 学生端 `ExamResult.vue` — 考试结果（纯Stub）

**现状**:
- `submitted` 硬编码为 `true`
- 仅显示 `a-result` 组件的"提交成功"图标和文字
- 无任何API调用
- 不显示分数、排名、答题详情

**已就绪的API**:
- `app/api/v1/scores.py` → `GET /{exam_id}/students/{account_id}` (学生答题详情)

**影响**: 学生考完试后看不到自己的成绩和答题情况

### 3.0.5 已开发组件未引用 — `Subjective.vue` 死代码

**现状**:
- `frontend/src/components/exam/Subjective.vue` 包含完整的主观题文件上传功能：
  - 文本回答区域（5000字限制）
  - 文件上传（50MB限制，支持图片/文档/压缩包）
  - 上传进度追踪、图片预览、文件类型检测
- 但该组件**从未被任何页面 import**
- `ExamPage.vue` 中主观题使用简单的 `<a-textarea>`，无文件上传能力
- 组件内含 broken import: `import type { SubjectiveUpload } from '@/layouts/ExamLayout.vue'`（文件不存在）

**影响**: 原始需求要求"主观题支持上传图片、文档、压缩包"，当前完全不满足

### 3.1 🟡 重要：后端功能缺失

#### 1. WebSocket 路由未注册

**现状**:
- `app/websocket/manager.py` 存在完整的 `ExamWebSocketManager` 类（连接管理、心跳、多端踢出、广播）
- 但**无 FastAPI WebSocket 路由端点**���册到应用
- `app/main.py` 中未 mount WebSocket 路由
- CLAUDE.md 描述的 `app/websocket/exam_ws.py` 文件**不存在**

**影响**: 实时答题同步、时间同步、强制提交推送、多端踢出推送均不工作

#### 2. 考试无更新/删除 API

**现状**:
- `app/api/v1/exams.py` 有 `POST /`（创建）、`GET /`（列表）、`GET /{id}`（详情）
- 无 `PUT /{id}` 更新考试信息
- 无 `DELETE /{id}` 删除草稿考试
- 创建后无法修改学生名单、考试时间等信息

**影响**: 教师创建考试后发现信息有误，只能重新创建，无法编辑

#### 3. 考试状态转换不触发自动提交

**现状**:
- Celery Beat 每60秒调用 `check_exam_status_transitions`
- 该任务将 OPEN→FINISHED 但**不调用** `auto_submit_exam` 提交剩余学生
- `auto_submit_exam` 方法存在但仅在考试手动关闭时可能被触发

**影响**: 考试时间到后，未提交学生的答案可能丢失

#### 4. 文件下载/服务端点缺失

**现状**:
- 上传的文件存储在 `./uploads/` 目录
- 无 `StaticFiles` mount 或下载 API
- `file_url` 字段存储路径但无法通过 HTTP 访问
- S3 上传为 stub (`# TODO: 实际上传到 S3`)

**影响**: 上传的资源文件无法被任何用户访问

---

### 3.2 🟡 重要：数据模型与架构规范偏离

| 问题 | 规范要求 | 实际实现 | 影响 |
|-----|---------|---------|-----|
| 分数列类型 | `DECIMAL(5,2)` | `Float` | 浮点精度问题，如 99.99 可能存储为 99.98999786 |
| `StudentExamAssignment` 唯一约束 | `(exam_id, account_id)` 应唯一 | 无唯一约束 | 同一学生可被分配到同一考试多次 |
| `submission_ip` 字段 | 提交时记录IP | 从未赋值 | 无法追踪提交来源 |
| `Resource` 软删除 | 使用 `SoftDeleteMixin` | 使用 `is_active` 字段 | 与其他模型不一致 |
| `Account.identity_no` | 考试账号必填(CHAR(18)) | `nullable=True` | 理论上可创建无身份证号的考试账号 |

---

### 3.3 🟡 重要：API 安全性问题

| 路由文件 | 问题 | 详情 |
|---------|-----|-----|
| `scores.py` | 无角色检查 | 任何登录用户可查看所有成绩、录入主观题分数 |
| `exams.py` | 无角色检查 | 任何登录用户可创建/发布/关闭考试 |
| `resources.py` | 上传无角色检查 | 仅 `get_resource` 检查教师权限，`upload`/`list` 对所有人开放 |
| `papers.py` | 无角色检查 | 任何登录用户可创建/修改试卷 |
| `questions.py` | 无角色检查 | 任何登录用户可增删改题目 |
| `exam_engine.py` | 有基本检查 | 检查学生分配关系，相对安全 |
